## ✅ 1. Fix deploy Vercel — error "URI malformed"

**Problema:** Al hacer deploy en Vercel, `vite build` fallaba con `URI malformed` en `vite:build-html`, abortando el build.

**Causa:** El `<head>` de `index.html` usaba el placeholder `%VITE_BIZ_EMOJI%` incrustado dentro de un data-URI SVG en el favicon. Durante el build, Vite recorre el HTML y ejecuta `decodeURI()` sobre los href; al encontrar `%VI`, `%TE...` (secuencias no válidas) lanzaba "URI malformed". Además, las variables `VITE_BIZ_*` no estaban definidas en Vercel, así que ni siquiera se hubieran sustituido.

**Cambios:**
- `index.html`: favicon estático válido (emoji 🌸 ya escapado) + `<title>` estático de respaldo + `apple-touch-icon` → `/logo.png`. Comentario explicando por qué NO usar sintaxis `%VITE_xxx%` ahí.
- `src/App.jsx`: `useEffect` que sincroniza `document.title` y el favicon/icono Apple en **runtime** con `import.meta.env.VITE_BIZ_NAME/SUBTITLE/EMOJI/LOGO` (con valores por defecto).
- `.env.example`: documentadas las 4 variables de branding que faltaban.

## ✅ 2. Fix ranking de "Servicios rentables"

**Problema:** Con una cita de Lifting ($85.000) + Tinte ($25.000) = $110.000, el ranking mostraba ambos servicios con $55.000 (repartía el total ÷ cantidad de servicios).

**Causa:** En `TopServices`, el cálculo hacía `total / names.length` — repartía el total de la cita a partes iguales entre todos los servicios.

**Fix:** Las citas **ya guardan** el precio individual de cada servicio en `servicePrices` (JSON `{id: precio}`). Now el ranking usa ese precio real, con fallbacks:
1. `appt.servicePrices[id]` → precio guardado en la cita ✅
2. Historial de precios del servicio a la fecha de la cita (para citas antiguas).
3. Precio actual del catálogo (`services.find(...)`).
4. Último recurso: repartir el total entre los servicios (comportamiento anterior).

## ✅ 3. Sin valores negativos — defensa en profundidad

**Frontend** (`src/App.jsx`):
- **Agregar gasto**: input `min="0"` + `onChange` con detección; botón deshabilitado si `Number(amount) < 0`; `add()` con `Math.max(0, Number(amount)||0)`.
- **Editar gasto**: igual + `saveEdit()` sanitiza con `Math.max(0, toN(editData.amount))`.
- **Nuevo servicio**: `min="0"` + `Math.max(0, Number(price)||0)` al guardar.
- **Editar servicio**: `min="0"` + `Math.max(0, Number(eP)||0)` al guardar.
- Domicilio ya estaba blindado (no se tocó).

**Backend** (`apps-script/Code.gs`):
- Función `clip0(v)`: devuelve `0` si `v` es NaN, negativo o no-numérico; el número tal cual si es ≥ 0.
- Función `sanitizePayload(b)`: clipa a 0 todo campo monetario del payload antes de persistir:
  - `services` → `price` (cada uno)
  - `expenses` → `amount` (cada uno)
  - `appointments` → `servicePrice`, `domicilioPrice`, `totalPrice`; y cada precio dentro de `servicePrices`
  - `calendarEvent` → `totalPrice`, `domicilioPrice`
- Llamada en `doPost` justo después del parseo + auth.
- `createCalEvent` también clipa los precios al construir la descripción.

Tan pronto el usuario quita el `-`, el mensaje desaparece y el botón se reactiva.

## ✅ 7. Citas futuras no se pueden marcar Completada/No asistió

En `ApptCard`, si la cita tiene `date > hoy` (es para mañana o más adelante) y está pendiente:
- El botón **"✓ Completada"** se deshabilita.
- El botón **"✗ No asistió"** se deshabilita y el cursor cambia a `not-allowed`.
- Aparece etiqueta amarilla "📅 Cita futura — no se puede completar aún".
- El botón **"💬 Recordatorio"** sigue habilitado (es para avisar al cliente que tiene una cita próxima).
- Los botones **"✏️ Editar"** y **"🗑️ Eliminar"** siguen disponibles.

Si la cita ya está marcada como Completada o No asistió, los botones quedan habilitados para poder revertir el estado.

## ✅ 9. UX de recordatorio 1h antes (manual, no automático)

**Aclaración honesta:** no es automático (no se envía solo — para eso se necesitaría la WhatsApp Cloud API oficial, que requiere configurar una app en Meta for Developers). Se mejoró la UX para que sea de 1 toque y no se pase.

### Badge animado "⏰ Recordar ahora" en cada cita próxima
En `ApptCard`, calcula cuántos minutos faltan para el inicio de la cita **hoy**. Si está pendiente y arranca en ≤ 60 min (o empezó hace menos de 10 min), la tarjeta se resalta:
- Borde con el color primario + halo a su alrededor.
- Badge superior izquierdo con animación pulsante (`remindPing`) que dice "⏰ Recordar ahora · 15:00" con la hora de la cita.

### Alerta "Por recordar" en el Dashboard
Justo bajo el saludo, cuando hay citas que califican, aparece una caja destacada con:
- Contador: "1 cita por recordar" / "N citas por recordar".
- Una fila por cada cita con el nombre del cliente, la hora y el botón verde "💬 Recordar" — un toque y se abre WhatsApp Web con el mensaje listo.

### Animación CSS
Añadido `@keyframes remindPing` en el `<style>` global (pulso con halo + escala, más visible que `pulse`).
